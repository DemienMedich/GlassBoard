# Обязательная поставка приложения

- Программа всегда должна иметь актуальную пользовательскую версию в формате SemVer `MAJOR.MINOR.PATCH`. Используй один канонический источник версии и передавай его в приложение, метаданные EXE, установщик и имя релизного артефакта. Не оставляй противоречащие друг другу или условные версии вроде `0.5`, `dev` и `latest`.
- Перед завершением релизной задачи собери настоящий установщик Windows (`Setup.exe` или `MSI`). Одна portable-папка или ZIP не считаются установщиком, если пользователь явно не попросил именно portable-вариант.
- Установщик должен поддерживать установку и обновление поверх предыдущей версии с постоянным идентификатором приложения, создавать корректную запись удаления и сохранять пользовательские данные. Не включай в него локальные базы, профили, фотографии, секреты, облачные настройки и другие данные разработчика.
- По возможности используй установку для текущего пользователя без прав администратора. Удаление программы не должно удалять пользовательские данные без отдельного явного выбора пользователя.
- Перед сдачей проверь в изолированном каталоге или профиле: запуск установщика, запуск установленного EXE без среды разработки в `PATH`, соответствие отображаемой версии версии установщика, обновление поверх предыдущей версии и штатное удаление. Не называй релиз готовым только потому, что проект скомпилировался.
- Зафиксируй в документации точный путь к установщику, его версию и результат проверки. Если проект публикуется через PharosHub, версия и исполняемый файл в manifest Хаба должны совпадать с проверенным релизом.

## GlassBoard и PharosHub

- Каноническая версия — `project(GlassBoard VERSION ...)` в `CMakeLists.txt`; из неё генерируются Windows-метаданные EXE, runtime-версия, заголовок окна, имя ZIP и установщика. При новом релизе увеличивай SemVer; уже опубликованные пакеты не перезаписывай.
- Идентификатор Хаба — `glass-board`, исполняемый файл — `GlassBoard.exe`. Постоянный AppId установщика: `{CBA09359-8F14-4A2D-8B13-6EF568933B14}`. Не меняй его при обновлениях.
- Сборка и упаковка: `installer/build-installer.ps1`; для уже собранного пакета — `-SkipPackage`. Проверка пакета: `verify_package.ps1`. Пакет содержит только EXE, Qt/CRT, документацию и лицензии.
- Проверяй install → upgrade → uninstall с отдельным тестовым AppId через `Z:\CPP\PharosHub\scripts\verify-installer-lifecycle.ps1`, используя настоящий предыдущий пакет. Пользовательские настройки хранятся штатно в QSettings `Faros/GlassBoard`; установщик их не изменяет и не удаляет.
- Smoke запускается только с `--data-dir <отдельный профиль>` и `--smoke-output <каталог доказательств>`: рисунки, захват экрана, настройки и результаты проверки не должны попадать в программный пакет или публикацию.
- Публикация проверенного релиза: `publish-hub.ps1 -LifecycleReport <report.json>`. Сверяй актуальность записи `glass-board` в `Z:\CPP\PharosHub\config\apps.json`. При добавлении новой записи выпускай обновлённый установщик Хаба с семейным каталогом без путей разработчика.
- Публикация должна обновлять и `Z:\CPP\PharosHub\package\config\apps.json`: запущенный локальный Хаб читает каталог рядом с EXE, а не исходный `config/apps.json`. `publish-hub.ps1` синхронизирует эту копию после успешной публикации. Не подменяй таким способом версию отдельной установленной копии в настройках Хаба.
- Общая папка — `Z:\Yandex.Disk\PharosHub`; manifest — `releases/glass-board/manifest.json`; установщики — `installers/glass-board`. Проверяй SHA-256 после копирования и установку через метод Хаба. Не называй локальную публикацию подтверждённой загрузкой на сервер Яндекс.Диска.
